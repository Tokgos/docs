`messages` 是按发生顺序组成的数组。Tikway 不会替应用保存对话历史：每次请求都需要由你的应用带上需要保留的历史消息。

## 消息角色

| `role` | 用途 |
| --- | --- |
| `developer` | 应用层指令，例如回答风格、边界和业务规则。较新的 OpenAI 模型优先使用此角色。 |
| `system` | 系统级指令；为兼容已有应用保留。 |
| `user` | 用户输入。 |
| `assistant` | 模型在前一轮生成的回复；继续对话时需要回传。 |
| `tool` | 应用执行函数后返回给模型的结果。 |

## 示例

第一轮模型回答后，将该条 assistant 消息加入历史；第二轮连同新问题再次发送：

```json
{
  "model": "openai/gpt-5.6-terra",
  "messages": [
    {
      "role": "developer",
      "content": "你是旅行规划助手，回答简洁且务实。"
    },
    {
      "role": "user",
      "content": "我只有两天时间游览杭州，第一天应该怎么安排？"
    },
    {
      "role": "assistant",
      "content": "第一天可围绕西湖展开：上午断桥至白堤，下午苏堤与花港观鱼，傍晚在湖滨欣赏日落。"
    },
    {
      "role": "user",
      "content": "我喜欢安静一点的路线，帮我把下午改一下。"
    }
  ]
}
```

<Tip>
  将长期固定的业务规则放在 `developer` 消息的前部；仅保留与当前任务相关的历史，可减少 Token 消耗并降低上下文噪声。
</Tip>
