Tikway 的公共 API 网关地址是 `https://api.tikway.ai`。同一把 Tikway API Key 可用于网关支持的不同协议；请求路径决定入站协议，请求中的模型标识决定调用哪个模型。

## 选择请求地址

| 协议 | SDK Base URL | 常用完整端点 |
| --- | --- | --- |
| OpenAI 兼容 | `https://api.tikway.ai/v1` | `POST https://api.tikway.ai/v1/chat/completions`、`POST https://api.tikway.ai/v1/responses` |
| Anthropic Messages | `https://api.tikway.ai` | `POST https://api.tikway.ai/v1/messages` |
| Gemini 原生 | `https://api.tikway.ai`，API 版本为 `v1beta` | `POST https://api.tikway.ai/v1beta/models/{model}:generateContent` |

使用 HTTPS。JSON 请求设置 `Content-Type: application/json`；上传文件的接口按对应 API 文档使用 `multipart/form-data`。`{model}` 是 Gemini 路径中的模型名称；其他接口通常在请求体的 `model` 字段中指定模型。模型标识以你在 Tikway 模型列表中看到的值为准。

<Note>
  Tikway 的 Anthropic 和 Gemini 原生端点分别位于 `/v1/messages` 与 `/v1beta/models/...`，无需在网关地址后加 `/anthropic` 或 `/gemini`。
</Note>

## 创建并保存 API Key

登录 [Tikway 控制台](https://tikway.ai)创建 API Key。将密钥放在服务端环境变量中，例如 `TIKWAY_API_KEY`，不要写入浏览器代码、移动端安装包、仓库或日志。密钥泄露后应停用并重新创建。

以下示例使用 shell 环境变量。运行前先设置 `TIKWAY_API_KEY`，并将示例模型替换为你有权调用的模型。

## 按协议传递密钥

| 请求协议 | 推荐鉴权请求头 | 其他请求头 |
| --- | --- | --- |
| OpenAI 兼容、图像、视频等 `/v1` 接口 | `Authorization: Bearer $TIKWAY_API_KEY` | JSON 请求使用 `Content-Type: application/json` |
| Anthropic Messages | `x-api-key: $TIKWAY_API_KEY` | `anthropic-version: 2023-06-01`、`Content-Type: application/json` |
| Gemini 原生 | `x-goog-api-key: $TIKWAY_API_KEY` | `Content-Type: application/json` |

网关也能识别 `X-API-Key` 请求头。新接入建议使用表中的原生写法，这样与各协议的 SDK 和本站 API Reference 一致。Gemini 密钥应放在请求头中。

### OpenAI 兼容示例

```bash
curl https://api.tikway.ai/v1/chat/completions \
  -H "Authorization: Bearer $TIKWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-5.6-terra",
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

OpenAI SDK 的 `base_url` 填 `https://api.tikway.ai/v1`，`api_key` 填 Tikway API Key。SDK 会添加 `Authorization: Bearer` 请求头。

### Anthropic Messages 示例

```bash
curl https://api.tikway.ai/v1/messages \
  -H "x-api-key: $TIKWAY_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

### Gemini 原生示例

```bash
curl 'https://api.tikway.ai/v1beta/models/gemini-2.5-flash:generateContent' \
  -H "x-goog-api-key: $TIKWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{"role": "user", "parts": [{"text": "你好"}]}]
  }'
```

## 鉴权失败时检查什么

网关无法识别或验证 API Key 时返回 `401`；密钥有效但无权访问目标资源时可能返回 `403`。检查请求是否发往正确的地址、密钥是否完整、请求头是否符合所选协议，以及目标模型是否对当前密钥开放。

响应头 `x-request-id` 可用于定位一次请求。错误体、限流头和重试方法见[状态码与响应](/zh/develop-guide/status-code-response)。
